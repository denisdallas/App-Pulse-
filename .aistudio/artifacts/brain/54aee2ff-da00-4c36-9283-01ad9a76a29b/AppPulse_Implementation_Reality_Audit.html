4. Data Architecture, Security & Persistence Risks

1. Flat JSON File Persistence (store.json)

Uses synchronous fs.writeFileSync on every state mutation. A sudden process exit or power cut during serialization can empty or corrupt the database.

2. Concurrency Overwrite Hazard

Multiple concurrent HTTP mutations modify in-memory arrays and flush the complete database without file locks or transactions.

3. Seed & Synthetic Review Pollution

Synthetic fallback reviews are inserted into the same array as genuine marketplace reviews without a provenance tag.

5. Top 5 Prioritized Issues to Resolve

Priority 1: Remove Synthetic Review Fallbacks

In server/store.ts, connector failures must record real error states instead of injecting fabricated reviews (violates PRD Rule 2E).

Priority 2: Migrate to Relational Database (Cloud SQL / PostgreSQL)

Provides durable ACID transactions, foreign keys linking themes to reviews, and isolated workspace partitions.

Priority 3: Implement Live Google Play & Microsoft Connectors

Replace stubs with actual public store scrapers or official APIs to match Steam's live retrieval capability.

Priority 4: Persistent Background Job Processing

Replace in-memory timeouts with durable job queue storing progress and surviving server restarts.

Priority 5: Real Outbound Email Transport (SMTP / Resend)

Connect genuine email transport for verifiable outreach dispatch and delivery receipts.

Recommended Smallest Safe Implementation Step (MVP)

Remove synthetic fallback generation from server/store.ts so intelligence data is 100% genuine; harden the Steam connector with pagination and error recovery; and connect real ping latency checks in Settings. This establishes pure data integrity prior to relational database provisioning.
